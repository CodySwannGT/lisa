# BDD behavior contract — coverage burndown

Generated from `bdd/features/*.feature` and `bdd/coverage-map.json`.
Regenerated by `BDD_BASE_SHA="$(git merge-base HEAD origin/HEAD)" bun run bdd:coverage:write`; never hand-edited.

## What each number means

Traceability coverage reports aligned mappings with evidence still present. **This is not execution coverage and not a pass rate.** Supplied execution outcomes remain separate. A waiver is an owned, dated IOU outside the obligation denominator; it is never coverage.

Feature documents live under [e2e-bdd-coverage/](e2e-bdd-coverage/) with the complete source path as their suffix. Complete local records live under [../bdd/reports/v1/features/](../bdd/reports/v1/features/).

The node scripts/... examples use installed host paths. In the Lisa monorepo, use BDD_COVERAGE_ROOT=. and the expo/copy-overwrite/scripts/ prefix instead; the coverage report still requires BDD_BASE_SHA.

Run `BDD_BASE_SHA="$(git merge-base HEAD origin/HEAD)" node scripts/check-bdd-coverage.mjs --report` for the current full runtime report. `node scripts/check-bdd-coverage.mjs --report` also emits diagnostic JSON, but can exit nonzero when a required baseline is absent or validation finds defects. CI publishes global counts, discovered-test inventory, floor evaluations and defects. Unassociated retirement records remain in `bdd/coverage-map.json`. This entrypoint intentionally stores no feature list or global counts.
