## Implementation and proof

1. Add one shipped verification controller. A local preflight resolves the
   installed package's real Antigravity destination and refuses an uncontained
   apply before spawning it. CLI absence never authorizes an apply.
2. Support genuine packaged applies in an explicitly inspected disposable
   Docker container. Copy inputs; never mount host paths or forward operator
   environment/credentials. Reject unsafe namespace, privilege and mount
   configurations before starting the container. Capture the image/container
   identity and package digest. This contains package installation, caches,
   Git configuration, detached reconciliation and vendor-owned paths too.
3. Capture declared host destinations before execution and compare them in
   failure paths as well as success. Unexpected changes stop execution and
   preserve current bytes privately; missing before-images remain unknown.
4. Run the actual installed bin.lisa with bootstrap and full apply. Require a
   full receipt and native allow/refuse cases against the emitted guard.
   Separate generated parity from native vendor activation, which is excluded.
5. Wire every generated Verify surface through the shared lifecycle contract.
   Root personally reviews code, security, behavior and scope. An independent
   verifier may execute empirical controls, without delegated code review.

Required access: project Bitwarden broker and live GitHub identity/repository
probes passed. Docker CLI is installed; normal `docker desktop start` brought
up the existing service; server probe returned 29.9.2. Runtime image and genuine
Node/npm/Bun/git/bash/jq tools are qualified before empirical apply execution.
No vendor account is required. No UI surface is changed.

The reported surface is CLI/filesystem: regression coverage must execute the
controller and real delivered CLI, including a failed-child route, and compare
all declared outside sentinels (both human and Lisa-managed). Unit protocol
fixtures are labelled and cannot establish native containment. Existing
integration harness: `tests/integration/`; native Docker proof is recorded
separately rather than silently skipped on machines without Docker.

Evidence markers: `packaged-apply-isolation-red-green` (reaching refusal and
unsafe container controls), `scoped-packaged-apply` (actual installed CLI and
guard), `global-destination-preservation` (complete before/after comparison),
`published-verification-preflight` (ordinary checks, normal merge and exact
published artifact). No required check is disabled. Canonical completion
requires all five scenarios and every marker; source green alone is not done.

Unknown prior real Antigravity bytes remain unknown. The existing real file
must not be changed by this work. Docker's own image/container bookkeeping is
expected infrastructure state; product configuration preservation is measured
separately and is not a claim that the entire host filesystem is immutable.
