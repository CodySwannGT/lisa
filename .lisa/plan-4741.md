## Design (from architecture-specialist)

### Config shape
`npmUpdater` is either today's single object or an array of the same objects, one per directory, each with today's key set exactly. The legacy object is read as a one-entry list. The policy digest is computed per entry, so root entries stay byte-identical. Each proposal covers exactly one directory.
A run selects its directory with a new reusable-workflow input `directory` (default '.'), exported as the workflow-level env `LISA_NPM_DIRECTORY`. The CLI keeps exactly 3 args. Multiple directories means the caller uses a matrix or one job per directory.

### Validation
- `validDirectory(d)` in lib/automation-provenance-contract.mjs:
  - a string of at most 200 characters, either "." or matching `^[A-Za-z0-9_][A-Za-z0-9_.-]{0,63}(?:/[A-Za-z0-9_][A-Za-z0-9_.-]{0,63}){0,7}$`
  - `path.posix.normalize(d)===d`
  - no `node_modules` segment
- `selectPolicy(config, directory)` in npm-update-policy.mjs:
  - the array has 1–8 entries, with no nested arrays
  - each entry passes validatePolicy, and directories are unique
  - exactly one entry matches, otherwise "directory is not a committed npm updater selection"
- validatePolicy :25-28 becomes `validDirectory(value.directory) && value.target==="main"`. A non-root entry requires `lisaOwner==="absent"` and no `runtime`.
- `baseline` (npm-update-prepare.mjs:57-86) checks:
  - `git ls-tree HEAD -- <dir>` is a 040000 tree
  - `<dir>/package.json` and `<dir>/package-lock.json` are regular 100644 blobs
  - `<dir>/bun.lock` is absent at HEAD and in the working tree
  - `realpathSync(join(cwd,dir))===join(cwd,dir)`
  - the root bun.lock is ignored for subdirectory proposals

### Risks
- The root `npm ci` in the hosted gate and the controller install still requires a root package-lock.json. A bun-only root still can't use the updater; this is out of scope, so file a follow-up.
- The signed descriptor gains an optional `directory`. Older hook verifiers reject subdirectory proposals (fail-safe); docs say to upgrade.
- Line budgets: prepare 291, gate 326, hosted-gate 310, cancel-origin 309. Put the helpers in contract/policy.
- If the subdirectory cancellation lifecycle is too heavy, refuse cancel-* for non-root with an explicit message and file a follow-up, but still swap in the resolver.
