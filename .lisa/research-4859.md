## 9. Conflicts, risks, and decisions the plan must make

1. **Existing tests assert the refusal being removed.** `tests/unit/scripts/npm-update-contract.test.ts:1545-1546` (`validatePolicy(POLICY, { tracker: "jira" })` must throw) and `tests/unit/scripts/npm-update-directory.test.ts:236-239` (`tracker: "linear"` must throw matching `/tracker/`). Both stay green unmodified only if a config lacking `jira.project` / `linear.teamKey` (and the GitHub repo identity) still throws with a message containing "tracker" (e.g. "configured jira tracker is missing jira.project"). Otherwise the AC "existing suites pass without modification" cannot hold. Decision: keep those configs failing with a "tracker" message.
2. **Credential name mismatch.** Issue says `JIRA_EMAIL`; repo convention is `JIRA_LOGIN` (alias `ATLASSIAN_API_TOKEN` for the token, `atlassian.email` as login fallback) in `lisa-work-item.mjs:2135-2147`, `quality.yml:265-271/5315-5319`, `ensure-quality-caller-scopes.ts:62-63`. Recommend reusing `jiraCredentials` semantics and `JIRA_LOGIN`; fail-closed messages name `JIRA_API_TOKEN`/`JIRA_LOGIN`/`LINEAR_API_KEY`. Needs an explicit decision since the issue text differs.
3. **Gate, host hook and provider proof verify the claim against GitHub — not listed in the issue's Technical Approach.** `github-attestation-provider.mjs` `claimState` :72-95 reads `repos/{queue}/issues/comments/{claimCommentId}` and requires a GitHub Bot with `claimActorId`; `automation-provenance-local.mjs` `canonicalContext` :224-228 requires `provider==="github"`; the gate broker allowlist (`npm-update-gh-requests.mjs:51-60, :136-141`, `gh-grants.mjs:107, :154-155`) is GitHub-only with decimal `issue`/`claim`. On Jira/Linear the claim author is the API-key user (not a GitHub Bot, not `claimActorId`), Linear comment IDs are UUIDs (fail `^[1-9]\d*$` at local :125 and gh-requests :58), and the gate/publish jobs have no tracker credentials while the controller helper env (`controller-factory.mjs:204-212`) is closed to GitHub vars (so `lisa-work-item.mjs backlink` for a Jira/Linear ref cannot authenticate). Decision needed: either (a) extend provider proof + broker + helper env to the adapter (large), or (b) for non-GitHub trackers, make claim identity a tracker-specific optional signed field and add a distinct `claimActorId` equivalent per vendor — while keeping the GitHub descriptor key set and values unchanged. This is the largest unplanned part of the work.
4. **Byte-exact round trips.** Leaf equality (`issue.body === draft.body`, `leaf.mjs:130-133`), HTML-comment markers parsed by `historicalFiling` (`leaf.mjs:155-186`) and body-regex discovery (`allocate.mjs:100-103`, `supersession.mjs:249-266`), and exact checkpoint comment-body matching (`checkpoint.mjs:233, :246`, chunk regex :85) all assume the tracker returns stored text byte-for-byte. Jira REST v3 stores ADF (descriptions and comments are not plain strings; HTML comments do not survive) and Linear normalizes Markdown (HTML comments may be stripped). Each adapter needs a lossless encoding (e.g. ADF `codeBlock` with exact text extraction for Jira; verified Markdown passthrough or fenced block for Linear) plus readback tests. Unverified against live APIs — must be proven with mocked-but-realistic fixtures and flagged as a residual risk.
5. **Prior-proposal discovery.** `discoverPrior` (`allocate.mjs:77-115`) relies on GitHub full-text search for a 64-hex selection key with `incomplete_results`/`total_count` guarantees. JQL `text ~` and Linear search tokenize/rank differently and give no completeness flag. Safer: an exact-match key (Jira label or entity property such as `lisa-npm-<selectionKey>`; Linear label or exact `description` filter on a marker) and a bounded complete listing. Required for the idempotency ACs.
6. **GitHub-only concepts with no mapping yet.** `policy.maintainer` is a GitHub login and `api.assignable` is a GitHub endpoint (Jira needs an accountId, Linear a user id); `type:Task`/`priority:medium` labels and `ensureLabels` (Jira issuetype `Task` + priority field; Linear labels/priority); `config.github.trustedHumanActorIds` for human holds; `children`/`blockers` (Jira subtasks + issue links; Linear children + relations); cancellation closes as `not_planned` with `closed_by` Bot (`cancellation.mjs:227-238`, `supersession.mjs:223-224`). The quality gates (`npm-update-quality.mjs:58, :74-77, :104-107`) and `buildDraft` text ("All-state GitHub query", "GitHub Actions runtime token") also embed GitHub wording. Decision: map each per adapter, or explicitly scope cancellation/supersession for Jira/Linear out (refuse with a clear message) in this item.
7. **Adapter boundary.** The code host stays GitHub for every tracker: `main()`, `gitCommit`, refs, pulls, Actions run/attempt reads, collaborator permission, attestations. Only tracker methods (create leaf, labels/state role, assignee, managed comment post/list/read, search, issue read incl. children/blockers, close/cancel) should move behind the adapter; `GitHub` class keeps code-host methods and remains the GitHub tracker adapter with zero behavior change.
8. **Signed-digest guard for GitHub.** Do not add keys to `automationProvenance` (its canonical JSON is `policySha256`) and do not add descriptor/proposal fields on the GitHub path; any vendor-only data must be optional fields present only when tracker ≠ github (the `directory` precedent, `optionalDirectoryFields` in `automation-provenance-contract.mjs:111-118`). `npm-update-root-identity.test.ts` goldens are the proof for the "byte-identical" AC. `queue` stays `policy.repository` (validated owner/repo at local :128-132) for all trackers unless a deliberate schema change is accepted.
9. **Workflow.** Add optional `workflow_call.secrets` (`JIRA_API_TOKEN`, `JIRA_LOGIN`, `LINEAR_API_KEY`) passed only to allocate/checkpoint/cancel steps (and gate/publish if decision 3a); stays contract major 1. Update caller docs (`docs/npm-updater.md:23, :89`, caller snippets) and keep `reusable-workflow-caller-scopes.test.ts:147-156` unchanged (secrets do not change `permissions`).
10. **Sync artifacts.** Every touched shipped script requires regenerating the helper graph, hash ledger, upstream evidence manifest, export surface, and `.prettierignore` for new files; new lib modules must enter `PRODUCER` in `npm-update-helper-inventory.mjs` (§7).
