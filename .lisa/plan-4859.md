## 0. Shape of the change (one PR, one change)

One change, not several: the seven ACs share one seam (a tracker adapter selected by `config.tracker`), and none of them can land usefully alone. The GitHub path is moved behind that seam as a thin wrapper that issues the **same calls, with the same arguments, in the same order** as today. Jira and Linear are two new adapters that **normalize vendor records into the GitHub-issue shape that `inspectLeaf` / `discoverPrior` / `checkpoint` already read**, so the claim, hold, quality and checkpoint logic is reused, not duplicated.

Out of scope here and refused with one plain-language sentence (§7): gate, publish, `cancel-prepare`, `cancel-checkpoint`, supersession of a cancelled prior, and **signed-origin recovery** (see decision D4 — the lead should confirm the follow-up covers it).

## 5. Lossless encodings (the exact-byte checks)

Every managed text — leaf body, `CLAIM`, announcement, checkpoint chunk and completion comments — is written and read through one codec per vendor, and every write is followed by an immediate readback that requires exact equality (fail closed otherwise).

**Jira (ADF).** Write: `{type:"doc",version:1,content:[{type:"codeBlock",content:[{type:"text",text}]}]}` (empty text → `content: []`). Read (`adfText`): a doc whose content is exactly one `codeBlock` → concatenation of its `text` nodes (the managed, lossless form); anything else (human comments) → text nodes joined, paragraphs separated by `\n` (lossy, used only for hold classification; can never equal a managed body because it was not written as a single code block — and the actor check still applies). HTML-comment markers survive because they are code-block text, not markup. Bound: Jira's 32,767-character text limit — `createLeaf`/`durableComment` refuse before writing if exceeded (chunks are ≤ 24,576 bytes; the leaf body is the only realistic risk, via the base64 filing evidence).

**Linear (Markdown).** Write: `` "````lisa\n" + text + "\n````" `` (four backticks so the leaf's own ```` ```gherkin ```` fence nests). Read (`unfence`): exact match of `/^````lisa\n([\s\S]*)\n````$/` → group 1; otherwise the raw body (human). Description and comment `body` use the same codec.

Readback normalization lives only in `adfText`/`unfence`; nothing else trims, re-wraps or case-folds. Human readability trade-off: the leaf renders as a code block in both trackers — accepted, because the AC needs the same sections byte-for-byte and native ADF/Markdown conversion strips the HTML-comment markers.

## 12. Risks to watch

1. **Vendor byte fidelity is unproven live.** Jira may trim a trailing newline in a code block (the leaf body ends with `\n`); Linear may rewrite fenced Markdown. Both fail closed ("live proposal specification differs") rather than misbehave, but a live smoke run on a sandbox project is required before calling this shipped. Say so in the PR.
2. **Jira create screens.** `priority`/`assignee` on create can 400 on projects that hide them. Fail closed; documented. The claim path already assigns when unassigned, so dropping `assignee` from create is the fallback if needed.
3. **Line budgets.** `npm-update-allocate.mjs` is at 299 and `lisa-npm-updater.mjs` at 284 — the edits must be net-negative / ≤ +10. Keep helpers in the new modules.
4. **Mock closures.** New modules must not import `npm-update-allocate`, `-supersession` or `-leaf` (closed mock factories elsewhere would throw on import).
5. **Shared credential identity.** If `JIRA_LOGIN` is a human (even the maintainer), that human's comments count as managed. Docs recommend a dedicated service account.
6. **Delivery order.** The workflow is live at `@main` before hosts apply the scripts; new env vars are harmless to old scripts, and new scripts with an old workflow fail closed naming the missing variable.
