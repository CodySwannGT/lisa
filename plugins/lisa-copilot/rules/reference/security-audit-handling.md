# Security Audit Handling

The procedure for a push or CI run blocked by the dependency security audit lives in the `lisa-security-audit-handling` skill: fix the vulnerable copy by refreshing the lockfile within the current range, upgrading the direct dependency, adding a targeted override to the fixed version, or replacing or removing the dependency. When none of those works, file a build-ready ticket with the evidence (advisory, dependency path, what each step tried) so the factory carries the replacement or removal; stop only when the next act needs access you lack, and say exactly what is missing. An audit exclusion is never the remedy. The audit's failure message names that skill, so it loads when it is needed instead of in every session. Never bypass the hook.
